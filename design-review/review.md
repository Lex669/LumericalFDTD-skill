# LumericalFDTD 官网设计评审

依据 huashu-design 的概念、哲学一致性、视觉层级、细节、功能和创新六维标准。评审日期：2026-10-27。针对当前线上版本，其 HTML 已与本地构建产物比对一致。

## 总体判断

**6.0 / 10。** 页面结构完整、风格统一，安装路径清楚；目前的主要问题是产品证据不足、字号过小，以及多处可替换到其他 AI 产品上的装饰和文案。

暖灰底与低饱和紫色本身可以保留，也符合最初的参考方向。需要加强的是形式与光学科研内容的联系。建议让“需求 → 模型 → 可验证结果”成为贯穿全页的视觉母题：同一个案例从需求输入，延伸到结构、场分布或光谱，以及实际文件产物。

| 维度 | 分数 | 判断 |
| --- | ---: | --- |
| 概念 / 立意 | 5 / 10 | 波前图提供了光学关联，但尚未把本项目特有的仿真过程与结果转化为主要视觉内容。 |
| 哲学一致性 | 7.5 / 10 | 暖灰、低饱和色、留白与排版风格一致，延续了参考网站的方向。 |
| 视觉层级 | 6.5 / 10 | 首屏标题和主按钮明确，但正文过小，大标题与实际可读信息之间的落差过大。 |

| 功能性 | 7 / 10 | 安装与示例入口明确，标签切换可用；内容可以更直接地回答科研用户的疑问。 |
| 创新性 | 4.5 / 10 | 大写英文眉题、章节编号、单词换色、重复箭头与泛化标语较多。 |

按 skill 的规则，概念得分为 5 时，总评封顶 6.0。该分数不是六项等权平均。

## 应保留的部分

- 清楚的主次按钮和安装入口，GitHub 链接容易找到。
- Claude Code / Codex 安装切换，与插件本身的双生态定位匹配。
- 从功能、安装、示例到产物说明的基本叙事骨架。
- 深浅主题、键盘标签页、移动导航和减少动效偏好的实现。
- 对示意图和本地软件许可作了说明，没有将装饰图当作真实结果。

## 修改建议（按优先级）

### 1. 重要：先修复实际阅读字号

桌面浏览器实测：功能正文 12px、论文说明 11px、依赖说明 11px、更新日志正文 11px、示例英文副标签 8px。手机端英文副标签进一步缩到 6px，示例页脚为 8px。不是截图缩放造成的视觉误差，而是计算样式中的实际字号。

这低于 skill 的“网页正文 ≥14px、标签 ≥12px”要求。科研用户需要阅读单位、依赖和命令，这些内容不应成为次要到难以辨认的装饰。

**修改规格：**

- 普通正文 15–16px，手机正文至少 14px，行高 1.7–1.9。
- 辅助说明和标签至少 12px。
- 安装代码至少 13–14px，长命令保留代码区横向滚动。
- 手机端优先删除多余英文副标签；需要保留的标签同样至少 12px。
- 字号上调后重新分配列宽与行距，不通过压缩字体把内容塞回旧高度。

代码位置：`docs/styles.css:511`（功能正文）、`:543`（论文说明）、`:706`（依赖正文）、`:988`（更新日志）、`:1399`（手机示例副标签）。

### 2. 重要：补一个真实、完整的仿真案例

当前首屏的波前图与题材相关，但它是装饰示意；“试着这样说”区域也只有输入需求和预期产物。用户仍然看不到插件实际完成工作的证据。

**建议：**用一个经过真实运行和核验的案例连接三步：

1. 输入：研究问题、材料、尺寸、光源或波长等必要参数。
2. 模型：实际几何结构或 Lumerical 模型截图。
3. 输出：实际场分布或光谱图，给出必要的轴、单位、归一化定义和参数说明。

在案例旁提供可访问的脚本、数据或报告入口。没有真实结果时保留明确的“演示 / 待补充”说明，不补造漂亮曲线或性能数字。

建议把这个案例放在首屏之后，使后续能力说明能回到同一任务。波前线条可以作为辅助语言保留。

代码位置：`docs/index.html:153` 附近的光学示意、`:530` 开始的示例区。

### 3. 重要：首屏更早说明产品形态与前置条件

“让光学仿真，从一句话开始”适合吸引注意，但用户还需要立即明白：这是插件、通过什么工具使用、计算发生在哪里、需要什么软件环境。

建议保留主标题，在其下增加一句明确描述：

> 面向 Claude Code 与 Codex 的本地 FDTD 自动化插件，连接你已有的 Ansys Lumerical 环境。

在安装按钮附近用至少 12px 的说明写明需要本地安装及有效许可。安装区继续保留详细依赖。主按钮可采用“查看安装命令”，减少点击后行为的不确定性。

代码位置：`docs/index.html:102`、`:108`、`:411`。

### 4. 重要：修正选中态文字对比度，扩大手机触控区

实测手机示例选中态英文副标签为 `#736b76`，底色为 `#e9e2ed`，对比度约 **4.05:1**，未达到 skill 的 4.5:1 正文要求。这与字号过小是两个独立问题。

此外，主题与菜单图标按钮为 32 × 32px，复制按钮高度为 30px。它们不是全部低于 WCAG AA 的最小目标尺寸，但可以采用更宽松的手机触控规格。

**建议：**

- 选中态辅助文字使用更深的颜色，例如当前 secondary 色，并重新实测至少 4.5:1；或直接删去无实质信息的英文副标签。
- 手机图标按钮、复制按钮提供至少 44px 高的触控区域。图标本身不必扩大到 44px。
- 在各主题、选中状态和手机断点分别检查。

代码位置：`docs/styles.css:203`、`:643`、`:1399`。

### 5. 优化：删除没有承担信息任务的模板装饰

现有 `LESS REPETITION. MORE DISCOVERY.`、`A LITTLE INSPIRATION`、`WHAT'S NEW` 等大写眉题，和章节编号、单词换色、遍布按钮的箭头一起，增加了通用 AI 落地页的感觉。

**建议：**

- 保留“建模 → 仿真 → 分析”的顺序编号，因为它表达过程。
- 功能、安装、示例、更新日志等普通章节不必统一编号。
- 中文标题已经完整时，可删除对应英文眉题。
- 外链箭头保留为行为提示；页内锚点与标签页无需普遍附加同一箭头。
- 将“准备好，开始探索”等章节标题改得更直接，例如“安装插件”；结束区避免再次重复首屏宣传语。

这样能把有限的注意力还给安装、科研问题与实际结果，不必更换整套配色。

代码位置：`docs/index.html:101`、`:336`、`:411`、`:532`、`:799`。

### 6. 优化：让页面节奏跟随内容量变化

桌面页面约 4468px 高，390px 手机页面约 6108px 高。长度本身不是错误，但当前多个大段空隙、重复双行标题和展开的长版本日志，使有效信息显得比实际更少。案例面板内大面积空白，也更适合容纳结果证据。

**建议：**

- 首屏 → 真实案例 → 能力与边界 → 安装 → 更多任务 → 更新，形成一次清楚的访问路径。
- 更新日志默认展示最新版本及简洁摘要，其余版本可展开或跳转完整记录；不删除维护所需的真实信息。
- 区块间距依据内容调整，例如桌面 72–96px、手机 48–64px，作为改版起点而非强制所有区块同距。
- 优先把空白用于模型和结果展示，再决定是否收紧页面。

代码位置：`docs/styles.css:455`、`docs/index.html:797`。

### 7. 优化：平台标识与技术文案更严谨

Claude Code 与 Codex 当前分别搭配 `✳` 和 `⌘` 字形。若将其作为平台身份展示，建议采用经核验的官方资源和使用规范；也可以只保留文字，降低品牌误认。项目自己的图标可以继续作为独立项目标识使用。

此外，需求中的波导截面、材料和模式等参数，在项目落地前仍可能需要补充确认。案例文案应明确这是“需求起点”，避免让示例看起来已经包含全部建模参数。

## 最先做的三件事

1. 普通正文提升到 15–16px，辅助文字至少 12px；删除手机上只有 6px 的英文副标签。
2. 精简通用英文眉题、非顺序章节编号及重复箭头，保留有信息功能的标记。
3. 把一个真实的“需求 → 模型 → 结果”案例提到首屏后，给出可核查的参数和产物。

以上仅为建议，本次没有修改或推送网站代码。若之后制作全新视觉方向，再按 skill 的三方向流程开展。
